# qt-ota

双击同目录的 `qt-ota.exe` 启动。程序用于当前 STM32H757 双核 HTTP OTA 协议。

1. 输入设备地址，默认 `192.168.10.2`。
2. 选择 CM7 或 CM4，点击“查询状态”。`running=0` 表示 A，`running=1` 表示 B。
3. 选择另一槽对应的 BIN，填写十进制版本号。
4. 点击“开始升级”，等待上传、校验、保存 pending 和设备复位。
5. 设备恢复后查询状态，并确认实际画面和业务运行正常。

程序自动检查目标槽链接入口、计算 CRC32，按 8192 字节分块上传。网络或服务暂时失败后按 1、2、4、5 秒退避重连，以设备 begin 返回的偏移续传，不自动取消会话；连续恢复失败达 60 秒后暂停保留任务（在请求结束时检查，每次请求超时 45 秒）。协议错误暂停并提示检查状态。取消只适用于 pending 保存之前。

关闭窗口保留任务并断开本地请求；重新打开会提示恢复，点击“开始升级”也可重新尝试恢复。原 BIN 必须保留在原路径且内容不变，恢复时检查 SHA256、CRC32 和长度。任务通过原子写入保存在用户本地应用数据目录的 `upload.json`。显式“取消上传”才请求设备 abort，确认成功后删除任务。

设备 RAM 会话空闲上限 60 秒、总时长上限 10 分钟；超时或设备复位后需要确认从头上传，Qt 本地保存任务不代表设备掉电后仍保留进度。end 请求失败时只查询目标槽运行状态、登记版本和长度，不自动重发 end 或 abort；结果未确认则保留任务。版本和长度匹配不替代整包校验及实际业务确认。

运行需要保留本目录 DLL 和 `platforms` 等插件目录，不能只复制 EXE。源码在 `src`，Windows PowerShell 执行 `./build.ps1` 可重新编译部署，脚本使用本机 Qt 5.11.1 / MinGW 5.3 32 位。

当前固件的 CM4 启动前提为 BCM4=0，由 CM7 写 handoff 后启动。程序每次只升级一个核，支持设备 RAM 会话内断点续传。

Windows PowerShell 执行 `./test-upload.ps1` 验证正常上传，`./test-recovery.ps1` 验证 begin/chunk 暂时错误、不完整 HTTP 回包、块未提交后恢复、强制退出后恢复、任务身份不匹配、设备会话失效和 end 结果查询。后者使用独立任务路径并清理测试文件；模拟块未提交不等同于真实设备半块收包或掉电试验。
