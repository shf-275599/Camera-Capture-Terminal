# YuNet 人脸检测与框稳定处理设计

## 目标与约束

用 YuNet 替代 Haar 正脸检测，改善姿态变化下的检测效果，并减少视频中的框抖动和短时闪烁。保留 Qt 5.11.1、MinGW 5.3 32 位、C++11、HTTP MJPEG 协议及最新帧处理架构。仅升级 OpenCV，不修改板端固件。

## 依赖与部署

使用 OpenCV 4.10.0，在 D:/OpenCV 下独立构建、安装，保留原 3.4.20 安装。只构建 core、imgproc、objdetect、dnn 及必要依赖，CPU 推理，关闭 GPU 和不需要的媒体后端。使用 face_detection_yunet_2023mar.onnx，并固定下载来源和校验值。保留模型许可证。

MinGW 5.3 的实际编译兼容性必须通过 Windows 构建验证；不以更换编译器或架构规避失败。模型通过 QFile 读入内存，再由 FaceDetectorYN 的 ONNX 缓冲区接口加载，以支持中文目录。部署脚本复制新版 DLL、模型及许可证；旧安装不删除。

实际构建发现内置 Protobuf 的 WrappedMutex 空函数体 constexpr 构造函数不兼容 GCC 5.3；安装脚本以可重复执行的单点源码替换改为 constexpr 默认构造函数，不改变常量初始化及互斥实现。

实际运行通过 GDB 定位到 DNN convBlock_F32 的 movaps 栈写入未对齐异常；OpenCV C/C++ 编译必须添加 -mstackrealign，以兼容 32 位 MinGW 的线程入口。修正后必须重新执行模型及协议测试。

## 检测流程

在现有 Processor 中进行 RGB 到 BGR 转换，等比例缩小到宽度最多 640，不放大小图。调用 FaceDetectorYN，score_threshold 为 0.8（0.9 在缩放双人样图中漏检，实测调为 0.8）、NMS 阈值为 0.3。框按实际横纵缩放比例映射回原图，裁剪到图像边界，拒绝非有限值和无效尺寸。

检测、稳定和绘制分开。静态图片测试只使用当前检测结果；视频使用稳定结果。界面人脸数量对应显示框数量，包含仍在短时保留范围内的框。模型或推理出错时清空稳定状态，显示错误，但继续播放图像。不静默回退 Haar。

## 框稳定处理

稳定器仅维护几何轨迹，不进行身份识别。使用单调毫秒时间戳。

- 按 IoU 从高到低对候选匹配排序，IoU 至少 0.3，执行一对一贪心匹配。同分按轨迹、检测索引决定顺序，保证可重复。
- 新轨迹需连续两次检测匹配后显示；一次未匹配就删除未确认轨迹。
- 已匹配框按时间进行指数平滑，位置和尺寸采用同一权重，时间常数初始为 60 ms。首次确认使用当前框，避免从未显示的旧位置缓慢追赶。
- 已确认轨迹短时漏检最多保留 150 ms，超过后不显示；距离最后一次观测超过 300 ms 则删除，即使新框重叠也必须重新确认。
- 图像尺寸变化、检测异常、连接 epoch 变化时清空轨迹。每次处理前检查 epoch，处理后仍保留原有 epoch 发布保护。
- 画面长时间没有处理时，下次更新先按真实经过时间过期，不按帧数累计。

这是稳定框位置的轻量方案，不提供遮挡期间运动预测或多人交叉时的身份保持保证。暂不加入光流、卡尔曼预测或独立检测线程。

## 代码边界

FaceDetector 负责模型加载、原始框检测、坐标映射及绘制，视频调用稳定器。小型独立 FaceStabilizer 负责几何匹配、平滑和生命周期，便于以合成框测试，不依赖模型。main.cpp 仅调整视频调用、epoch 重置和增加测试入口，不重构接收逻辑。

构建脚本、qmake 工程、README 和 AGENTS 同步切换版本及测试说明。

## 验证与验收

1. 在 Windows PowerShell 使用原 MinGW 编译 OpenCV 4.10.0 及应用，部署后运行根目录 EXE。
2. 确定性稳定器测试覆盖新目标确认、抖动衰减、多人顺序改变、一对一匹配、漏检保留及过期、长时间间隔、尺寸变化和显式重置。
3. 人脸样图测试覆盖原始检测、绿色框、空白无检出及并排多脸；对模型缺失/无效提供明确非零结果。中文部署目录验证模型内存加载。
4. 运行 --protocol-test 与 --smoke-test，确认接收、丢帧、重连及窗口启动没有回归。
5. 增加可复现的 CPU 检测耗时输出，与原处理时间含解码的统计区分。实际摄像头姿态、误检、框稳定性与帧率需要实机验证；未连接设备时明确报告未验证。

实际性能不足时先记录证据并调整输入尺寸，不承诺固定 FPS，不擅自增加跟踪系统或更换工具链。
