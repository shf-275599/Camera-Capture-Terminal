# Qt OTA 上传恢复设计

用户已确认采用“提示恢复”方案。本次实现 Qt 自动重连和本地任务持久化，设备 Flash 持久化仅评估，不改固件。

## 会话恢复

网络错误后按 1、2、4、5 秒退避，重复使用原核、长度、版本、CRC32、链接地址调用 begin。解析设备返回的 written，检查范围后据此发送后续数据，不凭本地已发送量猜测设备进度。连续恢复失败 60 秒后暂停并保留任务；每次请求有超时，因此检查在请求结束时执行。HTTP 协议错误暂停，不取消设备会话。

## 本地任务

使用 QSaveFile 原子保存 JSON 到用户本地应用数据目录，记录 URL、固件绝对路径、SHA256、长度、版本、CRC32、目标槽和上传阶段。begin 前保存，end 前保存结果待确认阶段。进度由设备返回，不必每块落盘。

正常关闭中止本地请求并保留任务，不向设备发送 abort；显式取消才调用 abort。重启发现任务时提示恢复，重新读取并校验文件身份。设备会话丢失时暂停，交互确认后才允许从零开始；已开始 end 的任务只查询状态，确认目标版本和长度及运行槽，否则保留结果待确认，不重发 end 或 abort。

## 验证

Windows PowerShell 构建、正常上传模拟、begin/chunk 响应丢失与半块断线、进程重开、文件身份变化、设备会话丢失、end 响应丢失。模拟验证客户端协议行为，不证明真实设备擦写及启动。
