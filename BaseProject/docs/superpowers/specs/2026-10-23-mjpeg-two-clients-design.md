# HTTP MJPEG 双观看连接

用户已确认双连接共享编码方案：浏览器与 Qt 同时连接 `/stream`，保留 LCD 和 OTA 路径。

一个静态编码任务复制 RGB565 快照并调用现有硬件 JPEG 编码。两个静态发送任务分别持有自己的 netconn。三块各 512 KiB 的 JPEG 缓冲位于 `0xD0700000..0xD087FFFF`；不覆盖最新发布帧和仍被发送任务引用的帧。通过临界区发布帧及获取、释放引用。发送完成后只取最新帧，慢连接跳过中间帧；连续三秒无发送进展则关闭连接。缓冲全部被占用时编码任务等待，不破坏帧。

最多两个观看连接；第三个连接或 OTA 活跃时返回 503。OTA 停流拒绝新连接，等待两个发送任务关闭连接并结束正在执行的编码。失败恢复沿用现有 resume 接口。

`mjpeg_fps_x10` 报告最近三秒仍在发送的最快连接帧率，不累加多客户端帧数。保留主页和 multipart 格式，Qt 不需要更换协议。

验证：Windows PowerShell 构建 CM7 A/B；实机检查双连接 JPEG 解码、第三连接 503、并发状态查询、单连接断开后另一个继续、重连，以及慢客户端和 OTA 停流。构建不能替代实机验证。
