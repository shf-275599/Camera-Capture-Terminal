# 轻量 ONNX 面部表情分类设计

## 目标与边界

在现有 YuNet 视频人脸框旁显示七类面部表情和模型分数：愤怒、厌恶、恐惧、高兴、中性、悲伤、惊讶。低分、过小或没有有效结果时显示“无法判断”。分类描述可见表情，不推断真实心理状态。保持 Qt 5.11.1、MinGW 5.3 32 位、OpenCV 4.10.0、CPU 推理及现有最新帧架构。

## 模型与预处理

选用 OpenCV Zoo facial_expression_recognition_mobilefacenet_2022july.onnx 浮点模型。下载后按官方 LFS SHA-256 校验，部署模型及其许可证；不增加 Python、推理运行库或重编 OpenCV 的需求。模型经 QFile 读入内存交给 OpenCV DNN，以兼容中文目录。

保留 YuNet 五个关键点，按官方标准五点执行不含反射的相似变换，将原始未画框图像对齐为 112×112。模型输入 RGB、NCHW，归一化为 (pixel/255 - 0.5)/0.5，按官方类别顺序解释输出。检查输出形状及有限值，对 logits 做稳定 softmax 产生模型分数。该分数不宣称为校准后的真实概率。

## 视频关联、节流与显示

扩展现有稳定器输出，包含稳定框、当前匹配检测索引及单调轨迹 ID，保留原框更新接口供既有测试使用。表情历史按轨迹 ID 维护，不按检测数组顺序维护；目标删除后清理历史。重连、分辨率变化、检测异常和显式重置均清空表情状态。

每张脸最多每 200 ms 推理一次。仅当前帧实际检测到且原图框宽高均至少 48 像素、五点有效的人脸可分类；不在画过框的图像上推理。按时间进行分类分数指数平滑，时间常数初始为 400 ms。最高分至少 0.6 才显示类别，否则显示“无法判断”；此阈值作为显示策略，需以实测评估。

同一轨迹在两次推理之间可显示缓存结果，但结果距当前时间超过 600 ms 或当前帧未检测到该脸时不显示旧表情。框旁使用中文标签和模型分数，画面边缘需保证文字尽量可见。人数仍按显示框统计。多人交叉不保证身份保持。

## 代码与错误处理

新增 ExpressionRecognizer 负责模型加载、五点对齐、推理及输出解析；小型表情状态组件负责分数平滑和更新时机，可用合成分数独立测试。FaceDetector 负责组织检测、稳定、表情分类和最后绘制，Processor 保持现有线程归属及 epoch 发布保护。

表情模型缺失或无效、推理失败不得中断视频或人脸框；单独报告表情错误、清空无效结果。状态栏分别显示人脸检测与表情推理耗时。模型失败不静默回退其他模型。

## 验证与验收

- Windows 原工具链编译、部署与启动，保留此前修复的 -mstackrealign。
- 合成分数测试覆盖 softmax、类别顺序、低分拒绝、平滑、200 ms 节流、600 ms 过期、多人分离及重置；几何测试覆盖关键点标准对齐与无效输入。
- 样图测试检查检测、对齐、七维有限分数、中文标签绘制、多人推理、推理耗时；不以一张未标注图片声称分类准确率达标。
- 验证中文部署路径和表情模型缺失、损坏时降级到正常视频与人脸框。
- 回归 --stabilizer-test、--face-test、--protocol-test、--smoke-test 和实机 --device-test。
- 记录实测耗时，不承诺固定 FPS；真实不同表情的准确率、多人快速交叉和长期动态体验需要现场样本验证。

同步更新模型安装/部署脚本、qmake 工程、README 和 AGENTS。实现只覆盖表情分类，不加入身份识别、数据上传、录制或表情统计报表。

## 实施验证记录

Windows 原工具链构建及根目录部署通过。表情状态/对齐、真实模型单脸/双脸和视频节流、原稳定器、人脸、协议、GUI 启动及 192.168.10.2 实机五帧解码测试均返回 0；实机测试时画面检出零张人脸，不作为真实动态表情准确率证据。最终样图预热后表情推理平均约 6.0 ms，YuNet 800×480 样图检测平均约 17.7 ms，均只代表该次测试。

隔离中文部署目录的模型加载通过；表情模型缺失、损坏时，人脸框和协议播放仍通过。已查看输出图片，中文标签绘制正常。表情模型目录没有独立 LICENSE 文件，部署保留 OpenCV Zoo 仓库 Apache-2.0 许可证及模型 README 来源说明。模型 SHA-256 为 4f61307602fc089ce20488a31d4e4614e3c9753a7d6c41578c854858b183e1a9。

单张未标注样图与缩放双图的类别结果存在变化；真实表情准确率及动态稳定性尚待现场样本评估，不以链路测试代替准确率验证。
